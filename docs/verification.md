# 0.1.0 验证记录

日期：2026-10-28。环境：Windows 11 x64（26200.8457）、WSL Arch、Codex CLI 0.164.0、系统 WebView2 131.0.2903.86。

## 构建与自动测试

- Rust 核心 12 项通过：primary/secondary 周窗口识别、非法值、真实 SQLite、账号隔离与 A→B→A 分段、失败后分段、修改间隔不重解释旧历史、保留与降采样、设置校验。
- Python 桥接 9 项通过：握手与交错通知、超时、断开与错误脱敏、旧协议身份读取、环境白名单、后代忽略 SIGTERM、父 EOF 落在回收期间、父管道保持打开时仍正常退出。
- 前端 5 项通过：历史空值、排序、分段、降采样与非法读数。
- TypeScript 检查、Vite 生产构建、Rust fmt 与 Windows 目标 Clippy `-D warnings` 通过。
- Windows GNU release 构建显式启用 `custom-protocol`，发布程序内嵌网页资源；包含 `WebView2Loader.dll` 的 ZIP 和 SHA-256 已生成。主程序约 7.2 MiB，压缩包约 3.2 MiB。
- 提供 Windows MSVC/NSIS 构建入口，但本次没有生成或验收 NSIS 安装包。

## 界面与真实连接

浏览器自动检查 1040×760、800×600、176×176：主界面无溢出，悬浮环背景透明。范围切换、键盘选点、设置保存、锁定/隐藏的界面交互均通过，未出现页面异常。普通浏览器没有悄悄回退到演示数据。

真正的 Windows 可执行程序使用 `--diagnose` 经 `wsl.exe`、Python 与当前 WSL Codex 返回成功，退出码 0，实测 Weekly 剩余 64%。这只是当时的读数，非固定配置。WSL 原有登录复用成功，没有再次登录。

关闭 Vite 服务后，从发布程序的 `http://tauri.localhost/` 获取真实 `online` 状态、额度与历史；截图来自真正 Windows WebView2。24 小时、7 天、30 天查询均返回本地已积累的真实采样。默认 Windows 子进程没有终端 PATH/代理的问题已通过 WSL 内环境白名单恢复解决。

通过本应用的原生 Windows 菜单消息验证锁定、解锁、显示与隐藏。锁定后检查整个悬浮窗口的 `WS_EX_TRANSPARENT` 和 `WS_EX_NOACTIVATE` 标志，确认穿透与不可激活；隐藏后 `IsWindowVisible=false`。关闭主面板后，其原生窗口被销毁，悬浮窗和应用继续运行；托盘退出命令正常结束应用。重启时原设置保留。

托盘注册已直接核验。图标在隐藏区时 `Shell_NotifyIconGetRect` 返回 `S_FALSE`，展开系统隐藏区后返回 `S_OK` 与有效矩形，说明隐藏时无法用矩形模拟点击。**实际鼠标左右点击托盘、手工拖动、物理拔插显示器及独占全屏场景尚未完成可靠验收。** 定向菜单消息与窗口标志检查不能代替这些手工项目。

## 资源测量

在主面板关闭、只显示圆环、没有开发服务器和调试端口的情况下，汇总主程序及其 WebView2 后代进程。启动预热 6 秒，采样约 10 秒；以下数值是本机一次短采样，并非跨机器保证，也不包含每分钟采集时 WSL 内临时 app-server 的峰值。

| 配置 | 工作集之和 | 私有提交之和 | 10 秒 CPU 时间 | 单核 CPU 比例 |
| --- | ---: | ---: | ---: | ---: |
| 默认 GPU 合成 | 437.52 MiB | 431.86 MiB | 0.0000 秒 | 0.00% |
| 软件合成（采用） | 374.67 MiB | 341.79 MiB | 0.0312 秒 | 0.31% |
| 最终发布程序内置软件合成参数、无外部环境覆盖 | 409.64 MiB | 366.07 MiB | 0.0469 秒 | 0.47% |

两次软件合成测量中主 exe 工作集约 30.33～63.32 MiB，其余主要是 WebView2；只报告 exe 会低估整体。测量受启动、系统组件和缓存状态影响，不应把两轮差值当作严格的渲染基准。工作集之和可能重复计算共享页面，私有提交也不等于实际物理驻留内存。软件合成降低了本次 GPU 资源开销，但仍有浏览器运行时的固定内存成本，不能称为数十 MiB 的完整常驻程序。
