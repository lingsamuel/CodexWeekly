# Codex 来源隔离与 Windows 本机支持

## 现状

额度数据库以账号哈希和采样时间为主键，所以同一账号在多个 WSL 发行版共用一条曲线。程序启动时读取全库最新的读数，可能回显其他实例的额度。会话统计已有发行版切换检查，异步结果和提示音去重仍需纳入来源切换流程。

## 来源选择与历史

- 面板的采集来源提供「Windows 本机」「WSL 默认发行版」和各个已安装的 WSL 发行版。旧设置继续对应原选项。未安装 WSL 时，仍可选择并使用 Windows 本机。
- 同一账号在 Windows 和各个 WSL 发行版共用一条额度曲线，不同账号维持各自的曲线。沿用现有账号哈希和历史记录，保留期仍为 90 天。升级后首次识别当前账号时，直接加载该账号已有历史。
- 额度实时读数、连接状态、离线缓存、会话详情和提示音按实际来源跟踪。手选某个 WSL 发行版和通过默认项选中同一个发行版时，对应同一来源。系统默认发行版变化后，下一次刷新识别新来源。
- 切换时撤下上一个实例的读数、曲线和会话状态。只有当前实例确认的账号可加载曲线。连接尚未成功时，可用当前实例此前记录的账号和读数回显自身缓存，并标记为离线。升级后的离线缓存从首次成功采集开始积累，因为旧采样只保留了账号。收到当前实例的新账号采样后，曲线切换至新账号的历史。
- 用切换序号标记采集和历史请求。即使快速切换 A → B → A，只有当前序号的结果可以更新界面或写入采样。

## Windows 本机采集

- 支持 Windows 原生 Codex CLI，包括 npm 安装，也支持从已安装的官方 Codex 桌面版定位其内置程序。沿用当前 Windows 用户的 Codex 登录和环境。无须 WSL 或 Windows Python。
- Windows 和 WSL 复用同一套 app-server 额度查询、账号识别和周额度解析。Windows 直接启动本机 Codex；WSL 保留环境恢复和子进程回收。采集只读额度和账号身份，存储仍只保留账号哈希。连接错误按当前来源提示。
- 老版 CLI 只返回邮箱时，只有新版同时确认额度账号 ID 和个人账号登录，才将该邮箱对应的历史加入同一曲线。组织工作区用稳定 ID 识别。旧协议缺少工作区 ID 时，其记录归于当前实例。
- 会话统计复用现有 `app-server proxy`，连接所选来源已有的 daemon。若没有 daemon 或会话接口不可用，隐藏会话气泡，额度继续更新。详情、完成状态和提示音去重均随实际来源隔离。诊断入口可选 Windows 或 WSL 来源。

## 验收

- 用同一账号从 Windows 和两个 WSL 发行版采集，核对三处共用一条曲线，最后读数和重启断线时的回显来自当前实例。再用另一个账号验证曲线切换。验证默认发行版和手选同一发行版使用同一份缓存。
- 用旧格式数据库升级，核对原有设置和历史记录得到保留，确认账号后可以继续查看原有曲线。模拟延迟请求和连续切换，确认只有当前切换序号的请求可以更新界面与历史。
- 在 Windows 验证本机 Codex 无需 WSL 即可读取额度。分别验证有可用 daemon 和无 daemon 时的会话行为，并回归已有 WSL 额度和会话采集。
