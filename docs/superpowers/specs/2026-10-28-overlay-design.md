# Codex Weekly Overlay 设计

状态：用户已确认方案（2026-10-28）。首发版本：0.1.0。

## 0.1.8：会话气泡详情与拖动

- 悬停蓝色或红色气泡时，从对应气泡旁动画展开会话列表。鼠标移入列表后保持展开，离开气泡和列表后收起。列表按会话更新时间从新到旧排列，显示 Project 名称和会话标题，条目多时可滚动。详情根据屏幕可用空间向左或向右展开，展开和收起时圆环留在原位。
- 蓝色和红色气泡均可按住鼠标左键拖动整个悬浮窗。拖动完成后复用现有流程保存位置。锁定时，气泡仍可悬停和拖动，展开的列表仍可悬停和滚动。额度圆环与其余区域继续鼠标穿透，悬浮窗继续保持不可聚焦。
- 沿用约 15 秒的会话状态刷新。在已知状态的基础上检测到新增工作中会话或未读完成结果时，自动展开对应列表 8 秒。两类同次新增时一并展示，8 秒内再次新增时重新计时。计时结束时仍处于悬停的列表继续显示，移开后收起。首次成功读取已有会话时只建立基准，隐藏悬浮窗时不弹出详情。
- 复用现有会话过滤、完成时间边界及回执检查。用会话和完成轮次的标识识别新增，支持总数不变但条目发生替换的情况。项目名优先通过 Codex 会话的 Project 归属读取，缺少可用名称时显示工作目录名并标为工作目录。标题缺失时显示“未命名会话”。项目名和标题仅用于本地悬浮窗，诊断报告沿用仅输出计数的格式。
- Windows 验收覆盖锁定时圆环穿透、两个气泡都能悬停和直接拖动、松手保存位置、悬浮窗不激活，以及屏幕边缘和跨 DPI 拖动。浏览器回归覆盖两类列表、8 秒收起和重新计时、悬停保持、总数不变的新增、初始加载和隐藏状态。

## 0.1.7：悬浮窗显示重置倒计时

按用户要求，将悬浮圆环的“本周剩余”替换为“X天Y小时后重置”。复用服务返回的 `resetsAt` 与既有重置标签格式化入口，按剩余完整小时拆分天和小时，每分钟按当前时间更新，断线时仍继续计时。时间缺失和已到期时沿用等待提示，不推断额度已重置。主面板继续显示重置日期和时间，托盘图标继续仅在额度或在线状态变化时重绘。

## 0.1.6：最小化状态下的悬浮窗恢复

真实故障现场确认：程序仍响应、显示设置为开启、正常位置保留，但 HWND 的 `IsIconic=true`、`showCmd=SW_SHOWMINIMIZED`，物理坐标为 `(-32000,-32000)`。这不是普通屏外移位，恢复位置/尺寸无法解除最小化。

- 悬浮窗禁用系统最小化入口；收到最小化消息时复用已有的延迟恢复流程，亮屏通知和 10 秒兜底也沿用同一恢复入口。
- 最小化会中断正在进行的拖动，既避免恢复被拖动状态永久阻塞，也避免将 `(-32000,-32000)` 写成用户位置。
- 用户显示设置为开启时，先用 `SW_SHOWNOACTIVATE` 解除最小化，再恢复保存位置、逻辑尺寸与 WebView 表面，不激活窗口。用户设置为隐藏时不擅自恢复显示，从托盘主动显示后再执行恢复。
- 隔离桌面回归必须复现“息屏期间被最小化→亮屏”，同时检查退出 iconic 状态、完整尺寸、保存位置和前台窗口不变。此前仅模拟移位/压扁的测试不能覆盖此故障。

## 0.1.5：红色气泡以本次程序启动时间为界

根据用户确认，红色气泡只统计最后一轮在本次程序启动时刻或之后完成、且仍有未读回执的非活动顶层会话。以轮次真实 `completedAt`（Unix 秒）比较，不用会话创建时间、`updatedAt` 或首次采集时间推测；原有会话在启动后完成新一轮也纳入。启动前完成的历史积压不纳入，时间缺失或无效时不猜测计数。

启动时刻在程序入口固定一次，断线重连、WSL 发行版切换和手动刷新都沿用该时刻，只有退出再启动才重设范围。蓝色工作中计数保持原规则。回执仍沿用 daemon，不写入已读标记；界面说明为“本次启动后完成且回执未读”，不声称确认用户实际读过。0 个时继续隐藏红色气泡。

## 0.1.4：息屏与显示器恢复

- 仅用户完成拖动时保存位置，系统因息屏、显示器重连或 DPI 切换产生的移动不覆盖用户位置。
- 亮屏、系统唤醒、工作区与 DPI 变化后，在主线程等待事件稳定并重新应用位置、176×176 逻辑尺寸和 WebView 客户区边界，恢复完整绘制；继续遵守锁定和隐藏设置。
- 复用既有显示器工作区与至少 48 物理像素可见的规则，允许跨屏摆放；副屏不可用时临时回退主屏，不覆盖保存位置，副屏恢复后回到用户位置。没有显示器信息时不移动窗口。
- 保留 10 秒显示器检查作为兜底，但息屏期间不移动窗口。自动测试覆盖几何与拖动保存规则；物理息屏、多屏和 DPI 切换需要实机验收，构建和离屏测试不能代替。

## 0.1.3：按用户明确反馈改为单条连续曲线

以下展示规则覆盖此前的分段和虚线设计：当前账号、所选时间范围内的有效采样按时间排序，直接复用 D3 B 样条拟合生成一条连续平滑实线与一个完整渐变面积。采集 `segment` 和窗口元数据不拆分展示路径，不绘制虚线桥接，仅保留最后一个采样点的标记；悬停仍读取真实值，数据库与账号隔离不变。

## 0.1.2 用户反馈与扩展

- 截图已确认曲线存在，缺口来自重启/断线分段。同一账号、同一已知 Weekly 重置窗口中不回升的相邻记录段以淡色虚线连接；额度重置、窗口未知或额度回升仍不跨段。真实采样段继续使用 D3 平滑曲线，缺失区间有明确虚线图例，不补造采样值。
- 托盘图标动态展示与悬浮窗同方向的余量圆环，中心仅显示整数余量（空间有限不附 `%`，完整百分比在提示中）。复用现有 SVG 圆环输出生成小型 RGBA 图像，不另写一套圆环算法；只在显示值或过期状态变化时更新。
- 已实测现有 Codex daemon 的 Unix 控制套接字使用 WebSocket，而非 stdio JSONL。通过 WSL 中的原生 `codex app-server proxy` 转发字节，Windows Rust 使用成熟 WebSocket 库握手；不建立外部监听服务，不重启 daemon，不创建或恢复会话。
- 当前本机协议的 `thread/list` 提供顶层交互会话的 `status` 和 `readStates`，`thread/turns/list` 可读取最后一轮状态。蓝色气泡统计 `active` 顶层会话（含等待确认），红色气泡统计有官方未读回执且最后一轮确已 `completed` 的非活动顶层会话；排除子代理。仅使用只读方法，不改变原有客户端的已读状态。
- 会话统计每 15 秒刷新，复用 daemon 代理连接，缓存未变化会话的完成状态；分页完整后才公布总数。接口/daemon 不可用时隐藏相应气泡，不将未知显示为 0，也不影响额度采集。0 个会话隐藏对应气泡，超过 99 显示 `99+`。蓝色置于圆环右上，红色置于右下，保持 176×176 窗口大小与原有穿透行为。

## 目标和边界

Windows 11 常驻额度悬浮窗，复用 WSL 的 Codex 登录，显示 Weekly 剩余百分比，并记录真实额度变化。采用 Rust、Tauri 2、TypeScript、React、CSS 与 SVG；不使用 C#、WinUI/WPF 或 Electron。WebView2 使用系统共享运行时。

## 数据连接

Windows Rust 后端使用 `wsl.exe` 在指定发行版执行内嵌的 Python 3 标准库桥接程序。桥接程序定位现有 Codex（包括 NVM 的 Node 路径），启动 `codex app-server`，通过 JSONL 执行 `initialize` → `initialized` → `account/rateLimits/read`，读完后关闭子进程。不复制、输出或向 Windows 暴露 OAuth 凭证，不创建对话或调用模型。

Windows 实测补充：`wsl.exe --exec` 不加载交互 shell，可能同时丢失 NVM PATH 和代理。桥接在 WSL 内以当前用户 shell 获取环境，仅导入 PATH、CODEX_HOME、NVM_DIR 与代理变量白名单；其余变量不导入，也不把整个环境发往 Windows。shell 初始化最多 5 秒。

默认使用 WSL 默认发行版，设置中可选择发行版；默认每 60 秒采样，可设置 30～3600 秒。手动刷新与定时任务共用单一采集入口，避免并行请求。额度采集空闲时没有额外 app-server；0.1.2 会话统计维持轻量代理连接复用已有 daemon，不拥有其生命周期。一次额度采集有明确超时和进程回收。

实测：本机 CLI 0.164.0 可通过已有登录读取周额度；`codex` 桶的 `primary.windowDurationMins = 10080`，`usedPercent = 27`。现有 0.165.0 daemon 的 proxy 握手未在探测期限内响应，因此首版采用已验证的独立 app-server，不依赖 daemon 内部控制协议。

## 额度语义

优先选择 `rateLimitsByLimitId.codex`，兼容旧协议 `rateLimits`。在 `primary` 与 `secondary` 中按 `windowDurationMins == 10080` 选择周窗口，不假定一定是 secondary。`remainingPercent = 100 - usedPercent`；非法、缺失或无法识别周窗口时显示明确错误，不显示为 100%。保留账号标识用于历史隔离，但不向前端公开账号 ID。不提供清空额度或兑换重置的写接口。

## 存储和异常

Windows 应用数据目录的 SQLite 保存采样、账号分组与设置。保留 90 天历史，图表按范围降采样并保留窗口重置分段。只存额度、时间、窗口及必要的账号隔离标识，不存凭证。数据库失败可见，不把未持久化状态报告为完整历史。

分段在采集时持久化，包括服务重置、已知失败后的下一次成功、账号变更（含 A→B→A）、设置变更、重启与超过当时采样间隔三倍的缺口。修改当前刷新间隔不会重解释旧历史。Windows 父管道关闭时 WSL 桥接取消采集并回收整个 app-server 进程组；守护线程使用原始 fd 读取，避免 Python 退出时的缓冲锁冲突。

连接失败保留上次有效读数并标记过期；启动没有历史时显示占位。重置时间过去也不能擅自推断额度变为 100%，等待服务返回。错误按 WSL/Codex 缺失、登录失效、协议不兼容、超时和一般连接失败分类，并提供可执行的恢复说明。

## 验证和交付

核心单元测试覆盖 primary/secondary 周窗口、旧/新协议、错误值、SQLite 存储、账号隔离、历史范围、过期和设置校验。桥接测试使用可控假 app-server 验证 JSONL 握手、超时、错误及清理，并用真实 WSL 凭证做只读集成验证。前端执行 TypeScript 检查、生产构建及浏览器交互/视觉检查。交付 Windows x64 可执行文件及可复现构建说明；实测记录分别说明已编译、已运行及未验证的手工项目。性能按真实进程 CPU/内存记录，不预先承诺未经测量的占用值。
